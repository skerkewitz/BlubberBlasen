# Raw notes: flow (unverified, from reading the code of version 1.4.0, 2026-11-22)

Working notes of the reader who wrote part of the spec. Line numbers fit that version only.


Conventions: "tick" = one call of game_tick (60 Hz). g.c = game.c. "timer" = state_timer. Pixel = screen px. Tile = 8 px.
Game version string "1.4.0" (game.h:28).

PART A: RULES
======================================================================

## A1. Constants (game.c:10-27, 80-82, internal.h)

## A2. Game states (GameState, internal.h:114-128) and every transition
State enum: TITLE, STORY, OPTIONS, TRANSITION, ROUND_INTRO, PLAY, ROUND_SKIP, PAUSE, CONTINUE, GAME_OVER, ENDING, NAME_ENTRY, HISCORES.
set_state(s) sets g_state and timer=0 (g.c:217). The timer is incremented once at the END of every tick (g.c:1537), so the first update of a new state sees timer==1 (and the state-entering tick itself already ends with timer 1).

R4. Power on: game_init -> hiscore_init, options_load, enter_title (g.c:1362-1393). Initial state TITLE.
R5. TITLE (g.c:373, 1428-1446): BG0 = title logo tiles (32x22 tiles at tile base 320, rows 0..21), HUD absent. Text: "HI" (8,25) red + best score 8 digits at (11,25); "SELECT: OPTIONS" (9,26) grey; "VERSION 1.4.0" (10,27) grey. "PUSH START" at (11,23) shown when (timer & 32) else row 23 cleared (so 32 ticks off, 32 on, starts off). Transitions:
   - any pad pressed SELECT -> OPTIONS (checked first).
   - else any pad pressed START -> starter = 0 if pad 1 pressed Start this tick else 1; if developer skip_story -> new_game(starter), else STORY.
   - else timer >= 600 -> HISCORES(highlight none).
   There is no attract/demo play.
R6. HISCORES (g.c:394, 1460-1466): clears layers; "BEST BLASTERS" at (9,4) yellow; table from row 9. Any Start press -> new_game(starter) directly (story skipped). timer >= 420 -> TITLE. Also entered after name entry/game over/ending with a highlighted rank (highlight rank row yellow; HISCORE_COUNT = none).
R7. STORY (g.c:1173-1239): 3 pages, text lines at column 4, rows 8,10,12,14,16,18 (6 lines, `story_text`), "START: SKIP" grey at (6,25). Start (any pad) -> new_game(story_starter) at once, no sound. B or Y, or timer >= 360 -> next page (sfx MENU, timer reset); after page 3 -> new_game(story_starter). Sprites: page 0: six rising bubbles at x 8 or 232 (alternate), y = 200-((g_frame+i*61)&191), tile BUBBLE0+phase{0,1,2,0,1,2}; page 1: 7 workers (walker, thrower, bouncer, flutter, hopper, spitter, dropper) at x=40+26i, y=40+(bob^(i&1)), tile base+bob, plus chaser at (120,172); page 2: both heroes at (96,172) and (144,172, mirrored, P2 palette). bob=(g_frame>>4)&1.
R8. OPTIONS (g.c:1106-1170): entered with Select on title. 4 rows at screen rows 8,11,14,17: cursor ">" col 4 yellow, label col 6, value col 21. Rows: MODE (ARCADE/PLUS), CO-OP RESCUE (OFF/ON), PLAYER 2 (HUMAN/CPU), BACK. Title "OPTIONS" (11,4) cyan. Help texts rows 21,22 (PLUS: "PLUS: DASH WITH L/R, AIM UP," / "PUSH: TOP. VACUUM: RIGHT."; ARCADE: "ARCADE: THE CLASSIC RULES."), "UP/DOWN, LEFT/RIGHT, START" (4,25). Input (any pad, priority order, one action per tick): UP (cursor up, wraps, sfx MENU) else DOWN (wraps) else LEFT/RIGHT/B/Y (toggle the row's option, sfx MENU; on BACK row: save and go to TITLE) else START/SELECT (save, TITLE). options_save is called on every exit (g.c:1159,1165). Options effects: plus = dash/aim-up/push bubble/vacuum on (player.c: try_dash, aim, shoot) and walls handling of bubbles; rescue = enemy touch traps instead of killing (player.c:227-231); p2_cpu = see R40.
R9. new_game(starter) (g.c:631-678): clear_objects (all objects cleared, every player PS_OFF, cpu=0, ids set); for both players: score digits=0, lives=0, extends_given=0, letters=0, powers=0, played=0, g_hud_changes++/g_hud_letter_changes++; counters (blown, popped, jumps, water, walked, food, water_kills, defeated, fire_kills, candies, queued) = 0; blasen_reset() (letter queues, turn, timer = 0); no_death=1; ending_delay=0; g_level=first_level (0 normally; developer option), g_round=first_level+1; cpu_reset(); P1.cpu = debug mask bit0; P2.cpu = (g_opt.p2_cpu || debug mask bit1); if P2 is CPU and starter==1, starter=0; join(starter); then every CPU-controlled player still OFF is joined too (3 lives, played[]=1 then reset to 0 -> no hiscore entry for a CPU). Then start_round().
R10. join(p) (g.c:615): lives=3, played[id]=1, player_start (state ALIVE, at spawn, invulnerable 120, facing=id), sfx START. Score, letters, powers, extends_given are NOT touched (score kept on continue/late join). join_by_start (g.c:625): cpu = debug mask bit (normally 0) then join: pressing Start on a pad always makes the slot human.
R11. start_round (g.c:568): first round of a game, no scroll: page=0, scroll_y=0, window_top=FIELD_Y(16, layer 0 hidden above y 16), level_load(g_level, 0) (whole room drawn at once) then round_intro().
R12. round_intro (g.c:506-565), called at the end of start_round and of every transition: clears bubbles, items, effects, enemies; g_skip_rounds=0; enemies_spawn_level (one enemy per level entry, in file order, in slot order; each starts at x = col*8, y = 16 (top of field), `entering`, hidden for `delay` frames, then walks to target x = col*8, y = 16 + row*8 - 8); player_enter_round for both; g_level_frames=0; g_hurry=0; g_freeze=0; hurry_text=0; clear_timer=0; both players lose POWER_GLOVE (other powers kept); boss round (kind BOSS): boss_spawn else boss_reset; door_open = no_death && kind==NORMAL && g_round in {20,40,50,60}; bg_clear(1) (layer 1 text cleared); HUD labels + values redrawn; box off. If kind==SECRET: start_secret_room() and return (R33). Otherwise: "ROUND" at (12,12) yellow, round number at (18,12) (2 digits, 3 from 100), floor name centred on row 13 cyan, "READY!" (13,15); darkened box rows 12..15, width = max(floor-name length,10) centred, 6 px padding; sfx START; state ROUND_INTRO.
   Floor index = (g_round-1)/10 by repeated subtraction capped at 10 subtractions: floor_names[]: THE CELLAR, PIPE WORKS, SPRING SHOP, BOILER ROOM, CONVEYOR HALLS, DRYING LOFTS, DYE WORKS, PUMP STATION, PRESSURE TANKS, THE CHIMNEY, TOP OF THE BOILER (g.c:117-120, 548-553).
R13. ROUND_INTRO tick (g.c:1468-1481): handle_start (an OFF player pressing Start joins; no pause here), player_update(p,0,0) for both (pad 0), enemies_update (entering enemies move; their AI is off because g_state != PLAY), draw_hud_values. Leaves when timer >= 120 AND no player is PS_ENTERING AND no enemy is entering: clears rows 12, 13, 15, then PLAY. Not run in intro: bubbles, items, effects, chaser, boss, counters, g_level_frames (stays 0).
R14. Transition (g.c:579-612): begin_transition: level_begin(g_level, page^1) (collision of the NEW room is active at once; the page is drawn 2 rows per tick), clear bubbles, items, effects, enemies, cpu_reset, player_enter_round for both, text rows 12,13,15 cleared, state TRANSITION. Each tick: player_update(p,0,0), level_draw(2 rows), g_scroll_y += 2 (mod 512). Done when g_scroll_y == target (256 if next page is page 1 else 0): 128 ticks; then page ^= 1, round_intro(). Layer 0 is 64 rows = two pages of 32 rows (page 0 rows 0..31, page 1 rows 32..63); room rows occupy page rows 2..27, rows 0,1 and 28..31 blank. The new room scrolls in from below (scroll goes downward through the map). HUD (layer 1) stays fixed and is redrawn each tick if changed.
R15. player_enter_round (player.c:248-272): OFF -> nothing. DYING -> player_killed (life lost now; if that was the last, stays OFF). RESCUE or other non-alive -> player_start (freed). Then dash/stun/carried cleared, state ENTERING, vx=vy=0. ENTERING moves 1 px per tick per axis towards the spawn (move_towards), drawn as a bubble sprite (BUBBLE0 + (g_frame>>3)&1); becomes ALIVE on arrival (player.c:491-499).
R16. PLAY: see A3. PAUSE (g.c:797-801, 1498-1503): in PLAY, a Start press by a player who is not PS_OFF (any of ALIVE/DYING/ENTERING/RESCUE) -> "PAUSE" at (13,13), sfx PAUSE, state PAUSE, update_play returns. In PAUSE nothing updates (no HUD redraw, no rng-dependent logic; the global rng still ticks); any pad's Start press (even from a player who is OFF; it does not join) clears row 13 and sets g_state=PLAY directly (timer not reset). Sprites and vacuum windows are still drawn while paused.
R17. CONTINUE (g.c:720-746, 748-773): when a life ends with lives==0 the player goes OFF; if players_in_game()==0 (a CPU partner that is still in the game counts) -> "CONTINUE?" at (11,12) yellow, number at (14,14), count=9, state CONTINUE (the room is frozen but drawn). Each tick: any pad Start -> that player joins (3 lives, score kept), rows 12 and 14 cleared, g_state=PLAY (room continues as it was; g_level_frames was reset to 0 at the death). Otherwise a 60-tick counter; every 60 ticks count-- (sfx MENU) and redraw; when the counter fires while count==0 -> rows 12,14 cleared, "GAME OVER" at (11,13) red, sfx GAMEOVER, state GAME_OVER. So digits show 9,8,...,0, each 60 ticks (600 ticks total). No limit on number of continues.
R18. GAME_OVER (g.c:1514-1518): timer >= 240 -> next_name_entry(0, none). Music stopped (music_update). Room, sprites and text stay.
R19. NAME_ENTRY (g.c:921-1016, 945-971, 974-984): for P1 then P2: a player enters if played[i] && hiscore_rank(score) < 5. Screen: "CONGRATULATIONS!" (8,4) yellow; "PLAYER 1"/"PLAYER 2" (8,7) green/cyan; "ENTER YOUR NAME" (8,8) cyan; "SCORE" (8,10) + 8 digits (15,10); "ROUND" (8,12) + g_round (15,12); help lines (5,21) "UP/DOWN  CHOOSE LETTER", (5,23) "B OR Y   CONFIRM", (5,25) "LEFT     BACK". Name chars cycle "ABCDEFGHIJKLMNOPQRSTUVWXYZ.!- " (30 chars incl. space; UP = next, wraps, DOWN = previous, wraps; sfx MENU). Name starts "AAA". Letters drawn at (14+i,16); the current one yellow and blinking (hidden while timer&16), those after the cursor shown as ".". Space is displayed as "_". B, Y or Start confirms the char: if position < 2 and not timed out, cursor advances and the NEXT char is pre-set to a copy of the one just confirmed; at position 2 (or at timeout) the entry is inserted (hiscore_insert(rank, name, score, g_round)), played[player]=0, next player checked. LEFT: back one position (only if position>0). Timeout: timer >= 1800 forces confirm every tick until finished, i.e. the rest of the name is accepted as is. Input is read from the pad of the entering player only (pressed[entry_player]), even for a human taking P2.
   After the last entry, HISCORES screen with highlight = rank of the last name entered (passed as `highlight`).
R20. ENDING (g.c:1022-1103): see A9.
R21. Transition summary table: TITLE -> STORY|OPTIONS|HISCORES; HISCORES -> TITLE|(new game) ; STORY -> (new game); OPTIONS -> TITLE; new_game -> start_round -> ROUND_INTRO -> PLAY; PLAY -> PAUSE|CONTINUE|ROUND_SKIP|TRANSITION|ENDING|(secret room via TRANSITION); ROUND_SKIP -> TRANSITION; TRANSITION -> ROUND_INTRO (or PLAY directly for the secret room); CONTINUE -> PLAY|GAME_OVER; GAME_OVER -> NAME_ENTRY|HISCORES; NAME_ENTRY -> NAME_ENTRY(next player)|HISCORES; ENDING -> NAME_ENTRY|HISCORES. After the hiscore list the game returns to TITLE after 420 ticks; there is no other way out of hiscores except a Start press.

## A3. The tick (game_tick, g.c:1395-1546)
R22. Input: the platform passes pad[2], SNES joypad words (bit layout game.h:35-46: B 0x8000, Y 0x4000, Select 0x2000, Start 0x1000, Up 0x0800, Down 0x0400, Left 0x0200, Right 0x0100, A 0x80, X 0x40, L 0x20, R 0x10). pad[i] = held buttons; pressed[i] = pad & ~prev_pad (rising edges, per player); prev_pad updated each tick. If player i is a CPU and in the game (state != OFF) its pad word comes from cpu_pad(). any_pressed = pressed[0] | pressed[1] (menus read any_pressed, so either pad drives every menu). Exception: P2 CPU taking over (R40).
R23. Order of one tick: (1) pad/pressed (2) debug_actions (dev builds) (3) g_sfx=0 (4) g_frame++ (5) one rng_next() draw "to keep the RNG ticking" (6) state switch (below) (7) CPU players' score digits zeroed (g_hud_changes++ if any digit was non-zero) (8) state_timer++ (9) sfx_flush: each requested effect id sounds once, in id order (10) music_update (11) debug_boxes (12) build_oam (sprites) (13) build_windows (colour windows) (14) video_frame. game_vblank uploads in vblank.
R24. music_update (g.c:177-194), asked every tick: TITLE, STORY, HISCORES, NAME_ENTRY, ENDING -> MUSIC_TITLE; GAME_OVER -> stop; every other state (incl. OPTIONS, CONTINUE, PAUSE) -> MUSIC_GAME.
R25. update_play order (g.c:807-918):
   1. handle_start: for i=0,1: Start pressed: if player i OFF -> join_by_start (joins mid-round, lands at its spawn, invulnerable 120, continues the loop); else (player in game, and state is PLAY) -> pause and return.
   2. g_level_frames++ (always, even if the rest is skipped below); if g_freeze, g_freeze--.
   3. player_update(P1, pad[0], pressed[0]); player_update(P2, ...). (player_update may call player_killed at the end of a death animation, which may change g_state to CONTINUE.)
   4. check_door(pressed); if g_state != PLAY return.
   5. if no player is PS_ALIVE: return (room frozen: no bubbles, enemies, items, effects, boss, counters, hurry logic; g_level_frames kept increasing).
   6. bubbles_update, enemies_update, chaser_update, boss_update, items_update, effects_update (incl. special/letter bubble emission), counters_check, powerup_round_tick, bonus_round_tick.
   7. if g_skip_rounds != 0 and level kind NORMAL: begin_round_skip, return. Otherwise g_skip_rounds=0.
   8. kind SECRET: if --secret_timer == 0 or no IT_FOOD item left: g_level = return_level; next_round(1); return (nothing else runs: no hurry, no extends).
      kind BOSS: boss HUD (R32), if boss_defeated and ++ending_delay >= 120: enter_ending; check_extra_lives for both; return.
   9. NORMAL: Hurry Up logic (R27), hurry text blink, check_extra_lives both players, clear logic (R29).
   After update_play, game_tick calls draw_hud_values (PLAY only if update_play ran, even when paused-return).
R26. Per-state work in the switch (g.c:1427-1523): TITLE R5; STORY update_story; OPTIONS update_options; ENDING update_ending; HISCORES R6; ROUND_INTRO R13; PLAY update_play + draw_hud_values; ROUND_SKIP draw_hud_values then after timer>=120: row 14 cleared, next_round(g_skip_rounds); PAUSE R16; CONTINUE update_continue; TRANSITION update_transition + draw_hud_values; GAME_OVER R18; NAME_ENTRY update_name_entry(pressed[entry_player]).

## A4. Hurry Up, chaser, clear
R27. Hurry Up (g.c:877-902): limit = level_defs[g_level].hurry_frames (seconds*60; 0 = never). When !g_hurry && limit && g_level_frames >= limit && enemies_count() > 0: g_hurry=1, hurry_text=120, ALL enemy slots angry, sfx HURRY. Chaser: when g_hurry && no chaser active && clear_timer==0 && enemies left && g_level_frames >= limit+600: chaser_spawn (one chaser per ALIVE player; P1's at (104,16), P2's at (136,16); speed starts 0.375 px/tick (FX(0,96)); every 32 frames (g_frame&31==0) +4/256 up to 2 px/tick; flies through walls, invulnerable; follows its own player) and sfx HURRY. "HURRY UP!" text at (11,13) orange blinks: each tick hurry_text-- then shown when (hurry_text & 8) else row 13 cleared (8 on / 8 off, ends cleared). Round-time counter g_level_frames is reset to 0 and g_hurry to 0 by player_killed (enemies calmed, chaser removed, thrown rocks cleared).
R28. Last enemy angry (g.c:891-893): every PLAY tick, if exactly 1 enemy remains, no bubble holds a trapped enemy (BS_TRAPPED or POPPING with enemy) and no enemy is still entering: all enemies angry. Independent of the Hurry flag.
R29. Round clear (g.c:908-917): if clear_timer running: --clear_timer; at 0 -> next_round(1). Else only on ticks where (g_level_frames & 7)==0: if enemies_count()==0 (active slots, entering ones included; defeated enemies flying as thrown items are no longer in the table, so they do not delay the clear) and trapped-bubble count==0: clear_timer=300, chaser removed, rocks removed, sfx CLEAR. Players have 300 ticks to collect food/gems; Start/pause still works; Hurry cannot fire (needs enemies left). BLASEN/umbrella during the countdown override it (R30).
R30. Round skip (g.c:467-499, 841-845, 1488-1496): round_skip(n, why, player) sets g_skip_rounds, skip_why, skip_player (last call in a tick wins). BLASEN completed -> n=1, SKIP_BLASEN; umbrella -> n=3, SKIP_UMBRELLA (item.c:106). In NORMAL rounds the round ends at once (end of the same update_play tick): rows 12-15 cleared, box behind rows 12..14 (BLASEN: "CONGRATULATIONS!" yellow row 12, "BLASEN COLLECTED" cyan row 13, "BLUBBER GETS AN EXTRA LIFE" (P1) / "BLASI GETS AN EXTRA LIFE" (P2) row 14, all centred) or rows 12..13 (umbrella: "UMBRELLA!" yellow, "SKIP 3 ROUNDS" cyan); state ROUND_SKIP; room frozen (no player/enemy updates) for 120 ticks (timer>=120), HUD still redrawn; then next_round(g_skip_rounds). In boss or secret rooms g_skip_rounds is discarded (set to 0 at step 7/8; the life of BLASEN is still given).
R31. next_round(advance) (g.c:681-690): repeat advance times: if g_level < boss_level then g_level++, g_round++ (stops at the boss round; the boss level is the last level with kind BOSS, normally index 99 = round 100). Then begin_transition. So rounds = levels; the umbrella from round 98 goes to round 100, never past it.
R32. Boss round HUD (g.c:856-865): while boss_fighting: "BOILER" red at (5,2); 12 cells at (12..23, 2) orange, cell k "#" if 2k < boss hp else "-" (hp max 24; lit cells = ceil(hp/2)); otherwise row 2 cleared and the round number redrawn at (0,2) each tick. The boss has 24 HP, popping the trapped giant bubble gives +100000 to the toucher (boss.c:170), the ending starts 120 ticks after boss_defeated (ending_delay counts only boss-round ticks that reach the boss branch).

## A5. Round progression and special rooms
R33. Level data (level_data.h, tools/README.md): 101 levels sorted by file name: round001..round100 (index 0..99), secret (index 100). round100 has kind BOSS (settings `boss 1`), secret has kind SECRET (`secret 1`); all others NORMAL. Enemy types: 1 walker, 2 bouncer, 3 thrower, 4 flutter, 5 hopper, 6 spitter, 7 dropper, 8 shield. .map layout: 832 bytes static + 832 airflow + int32 enemy count + 4 int32 per enemy (x, y, type, looking left). level_defs[] are sorted so the order of play is the file order.
