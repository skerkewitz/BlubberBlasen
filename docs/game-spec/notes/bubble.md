# Raw notes: bubble (unverified, from reading the code of version 1.4.0, 2026-11-22)

Working notes of the reader who wrote part of the spec. Line numbers fit that version only.


Units: px = screen pixels, positions are top-left of the 16x16 sprite, 8.8 fixed point; PX(v) = integer pixel part. "tick" = 1/60 s frame. Speeds in px per tick. Screen 256x224, HUD rows 0-1 (FIELD_Y = 16), room = 32x26 tiles, FIELD_BOTTOM = 224.
Tick order (game.c:~815-835): players update (shooting, bubble touch) -> check_door -> bubbles_update -> enemies_update -> chaser_update -> boss_update -> items_update -> effects_update -> counters/power-up/bonus ticks -> round-end tests. If nobody is alive (all dying) nothing from bubbles_update on runs.
Overlap test `overlap(a,b,w,h)` (game.c:208): |PX(ax)-PX(bx)| < w AND |PX(ay)-PX(by)| < h, on top-left pixels, strictly less.

PART A: RULES
==================================================================

## A1. Object table and slots
R1. 16 bubble slots (MAX_BUBBLES, internal.h:215), 2 push shots (one per player, bubble.c:57). Bubble states: OFF, SHOOT (fired, flying), FLOAT (free), TRAPPED (holds an enemy), POPPING (fuse lit). Kinds: NORMAL, WATER, FIRE, LIGHTNING, LETTER (internal.h:216-217).
R2. New bubble (fired or special): alloc_bubble (bubble.c:76): first free slot by index; if none, the oldest plain bubble (state FLOAT, kind NORMAL, biggest age) is silently replaced (no pop, no score, no burst effect); if there is none (all are shot/trapped/popping/special) the new bubble is simply not created.
R3. bubbles_clear (bubble.c:59): all bubbles off, both push shots off, vacuums cleared, chain counter 0. Called at round intro (game.c:508), new game etc.

## A2. Firing a bubble (bubble_shoot bubble.c:121; caller player.c:449-465)
R4. Fire = button Y press (edge), only when the player's shoot_cooldown is 0. Cooldown after a shot 15 ticks (7 with the rate candy) (player.c:26-27,462). Shoot pose 10 ticks.
R5. Spawn position: side shot: player x +8 (facing right) or -8 (facing left), same y as player (player.c:415-416). Plus mode with Up held: x = player x, y = player y - 12, direction UP (player.c:408-413). x is then clamped to the room (R8).
R6. Flight: speed 4 px/tick (6 with speed candy), SHOOT_FRAMES 8 (14 with range candy) (bubble.c:16-17,40-41,137-138). Direction fixed LEFT/RIGHT/UP. Per tick the bubble moves first, then the checks of R9 run. Because age is incremented before update_shot (bubble.c:580) and the stop test is `age > shot_frames` (bubble.c:366), the bubble moves 9 times (36 px; 15 moves = 60 px with range; 54 px with speed; 90 px with both), not 8. On the tick it turns into a floating bubble the move of that tick has already happened; it starts drifting on the next tick.
R7. A fired bubble counts `g_count.blown` (cap 255; unlocks the range candy) only if a bubble was actually created (bubble.c:139). Bubble Ring (+100 per shot) and the sound are given by player.c even when no bubble was created or when the shot popped at once.
R8. Horizontal limits for bubbles: level_clamp_x (level.c:123): the bubble's centre x (x+8) is kept in 22..234, i.e. left edge 14..226 px. Hitting this clamp (x did not change in the move) ends the flight (stop) (bubble.c:355).
R9. Flight checks per tick, in this order (update_shot bubble.c:340-375):
   1. Move (side: +-speed then clamp; UP: if PX(y) < 22 + PX(speed) + 1 then y = 22 and stop, else y -= speed). 22 = TOP_LIMIT = FIELD_Y+6.
   2. Plus mode only: if the leading edge hits a solid tile, undo the move (back to the position before this tick) and stop (R10). In that case the enemy test is skipped.
   3. Otherwise catch_enemy (R14); if it used the bubble, end of update.
   4. If stop, or age > shot_frames, or boss_touch(x,y) (R41): the bubble becomes FLOAT, direction UP, age is kept (not reset). In the boss round (level kind BOSS) the bubble then also becomes a LIGHTNING bubble with age = 1 (R40).
R10. Walls (Plus only, shot_hits_wall bubble.c:324): the test point is the bubble centre (x+8,y+8) moved 6 px (SHOT_EDGE) in the flying direction (UP: y-6). Solid tile there = stop in front of the wall. Classic: fired bubbles ignore all inner walls and platforms and only stop at the room's side clamp (R8) and, for UP (not reachable in Classic), the ceiling. level_solid_px: anything above FIELD_Y is not solid; left/right outside the map is solid; above/below the map is open (level.c:17-36).
R11. Point-blank in Plus (bubble.c:115-127): if the spawn centre (x+8,y+8) is already inside a solid tile, no bubble is made: a burst puff appears, pop sound, and nothing is counted. (Classic: never.)
R12. A bubble spawned against the side wall is clamped (level_clamp_x at spawn, bubble.c:150), the first move then does not change x, so it stops at once and floats; catch_enemy still runs that tick.
R13. Animation phase: anim = rng & 3 at fire (bubble.c:146); sprite frame = {0,1,2,1}[((age>>3)+anim)&3], i.e. 8 ticks per frame (bubbles_draw bubble.c:641-648).

## A3. Trapping enemies (catch_enemy bubble.c:294)
R14. A moving empty bubble (fired, SHOOT, or a normal FLOAT bubble that is being shoved, R30) traps the first enemy (lowest index) that is active, not "entering", and overlaps with w=12,h=12 (strict) on top-left pixels. One bubble traps one enemy. Floating bubbles that merely drift never trap; walking an enemy into a drifting bubble does nothing.
R15. Shield enemy (Riveter): if enemy_shield_blocks(e, bubble x) is true (bubble came from the plate side), the bubble bursts with a puff and pop sound, no trap, no score, bubble gone (bubble.c:299-304). Otherwise it traps.
R16. Trap: the enemy is removed (active=0), trap sound; the bubble stays where the BUBBLE is (not at the enemy), state TRAPPED, trapped=1, age = 0 (new 300 tick clock), direction UP, momentum 0; stores enemy type and the enemy's angry flag (only for the picture: red tint) (bubble.c:305-314).
R17. Trapped bubble drift: 0.30 px/tick (TRAP_SPEED FX(0,77)); an empty float bubble 0.35 px/tick (FX(0,90)) (bubble.c:18-19,608).
R18. Escape: when a TRAPPED bubble has age >= 300 (TRAP_LIFE; 5 s after trapping) it bursts (puff) and the enemy is respawned at the bubble's position, always angry, facing left or right by a random bit (bubble.c:618-622). Warning: ring turns orange at age >= 120 (TRAP_ORANGE = 300-180), red from age >= 210 (TRAP_RED = 300-90) and from then flashes (hidden on ticks where age&4 is set: 4 ticks off, 4 on) (bubble.c:669-678). The small enemy picture inside is drawn on top of the ring; angry enemies in the red palette. A popping (fuse lit) trapped bubble keeps drawing as ring+enemy until it bursts.
R19. A trapped bubble whose enemy is later turned into a gem by an item (Soap Star / Rinse Wave): bubbles_trapped_to_gems (bubble.c:165): every TRAPPED bubble and every POPPING bubble that holds an enemy becomes a thrown 8,000 gem (GEM_TIER 3), thrown right from even slot indices and left from odd slot indices; the bubble disappears; returns the count.
R20. bubbles_trapped_count (bubble.c:199) = TRAPPED + POPPING-with-enemy; used by the round: the round does not end and the "last enemy gets angry" rule does not fire while any exists (game.c:891,912).

## A4. Floating: drift, air, limits
R21. A FLOAT/TRAPPED bubble each tick (bubbles_update bubble.c:596-609), by priority: (1) if it has momentum (vx or vy not 0, a shove) it slides (R31); else (2) if inside a vacuum it is pulled/held (vacuum_move, Plus only, vacuum.c:193), position clamped; else (3) airflow drift.
R22. Airflow: every 16 ticks of age (age & 15 == 0, age counted since the bubble was fired/spawned/trapped) the bubble reads the air direction of the tile under its CENTRE (x+8, y+8) (level_air_at level.c:57; 0 = no air, 1 up, 2 down, 3 left, 4 right; outside rows 16..223 = none). Between readings it keeps the last direction. Then it moves 0.35 (0.30 trapped) px in that direction. Only one axis moves at a time (4 directions, no diagonals). Direction stored on a shot turning to float, on special spawn and on trapping is UP, so for the first ticks until the next multiple of 16 the bubble floats up.
R23. Tile with no air direction: the bubble picks a random direction among up/down/left/right (1 + (rng & 3)) at each such reading, i.e. every 16 ticks it may turn randomly while in a no-air tile (bubble.c:604-606).
R24. Floating bubbles ignore walls and platforms entirely (drift, push, slide, vacuum): they pass through solid tiles; only the clamp below stops them.
R25. clamp_bubble (bubble.c:209): x per R8 (left edge 14..226). y: if PX(y) < 22 or PX(y) >= 224 the bubble is put at y = 22 (the ceiling; also the wrap case); else if PX(y) > 202 (BOTTOM_LIMIT = 224-8-14) y = 202. So bubbles never leave the room vertically; they collect at the top (y 22) and cannot wrap. Applied after every drift, push, pull and slide step.
R26. Normal empty bubble life: age >= 600 (10 s from firing; the 8-9 ticks of flight count, so ~591 ticks of floating) -> a puff, bubble gone, no score, no chain, not counted as popped (bubble.c:615-617). Colour: normal from age 0..419, orange from age >= 420 (BUBBLE_ORANGE = 600-180), red from age >= 540 (600-60), and from 540 flashing (hidden when age&4) (bubble.c:682-691). A bubble in flight (SHOOT) is never orange/red. Colours by age after being popped-state frozen too.
R27. Special / letter bubble life: SPECIAL_LIFE 1200 ticks (20 s) from spawn (age starts at 1); then it disappears silently ("drifts away"), no burst. Draws flashing (hidden when age&4) from age >= 1080 (bubble.c:611-614,651-654). No orange/red for them.

## A5. Separation and "soap" clinging (separate bubble.c:384)
Runs once per tick after all bubbles were updated, over all pairs i<j in slot order, only for bubbles that are FLOAT or TRAPPED (not SHOOT, not POPPING). Each pair adjusts both bubbles immediately (not simultaneous), clamp_bubble after each adjustment. Distances on integer pixels (PX).
R28. |dx| >= 24 or |dy| >= 24 (STICK_REACH): no interaction.
R29. Else if |dx| >= 13 or |dy| >= 13 (PUSH_REACH): cling: on each axis whose gap is > 13 (strictly; exactly 13 is no pull) both bubbles are pulled 0.25 px/tick toward each other (STICK_PULL FX(0,64)), the two axes independent. Skipped by debug switch DBG_NO_STICKY. (comment bubble.c:410-413)
R30. Else (both |dx| < 13 and |dy| < 13): push apart along the dominant axis (|dx| >= |dy| -> x axis, tie -> x). Each bubble is moved by (13 - |d|) * 16 / 256 px = (13-|d|)/16 px (0.8125 px at distance 0, 1/16 px at 12). Direction: away from each other (x: if dx>0 bubble a (lower index) goes right; dx == 0: a goes right if its slot index i is odd, else left; y: dy>0 a goes down, else up, dy == 0 not possible on the y branch). Result: bubbles settle ~13 px apart (3 px overlap of sprites), which is inside chain reach 18.
(Shoved and vacuumed bubbles are also pushed/clung by this; clamp_bubble applied.)

## A6. Push bubble (Plus mode only; player.c:432-440, bubble.c:179,503)
R30a. Button X (edge). One per player at a time (push_shoot returns 0 while one is active: no sound, no pose). Costs nothing. Spawn same as a fired bubble (side +-8 px, or Up held: x, y-12), x clamped. Sound + 10 tick shoot pose.
R30b. Flight: 6 px/tick (PUSH_SPEED), side or UP only. It is updated in bubbles_update BEFORE the bubbles (after vacuums_tick), players 0 then 1, and also moves in the tick it was spawned (spawned by player_update earlier in the same tick). UP: if PX(y) < 22+6+1 = 29 it bursts at the ceiling without moving; else y -= 6. Passes through inner walls and platforms; side clamp (R8) bursts it (`x == before`). Max life: bursts when age >= 12 (12 moves = 72 px). Burst = puff, push shot off.
R30c. Hit tests each tick after the move, in this order, first match ends it (box PUSH_HIT = 10: overlap w=h=10 strict, top-left pixels):
   1. floating bubbles (FLOAT or TRAPPED) in slot order: if special/letter kind -> bubble_pop(b, dir = -1 for LEFT, +1 otherwise incl. UP, owner = pusher) i.e. as if touched; if normal (empty or trapped) -> shove (R31) + pop sound. Then the push bursts. Shot (SHOOT) and popping bubbles are not hit (so a push bubble overtakes a bubble in flight).
   2. enemy shots (item IT_ROCK of any kind incl. the boss's soot): removed, pop sound, push bursts.
   3. enemies (active, not entering): push bursts, nothing happens (also on a shielded one).
   4. the other player (PS_ALIVE or PS_RESCUE, not the owner): bursts, nothing.
   5. boss_touch (R41), side wall, or age >= 12: bursts.
   It collects/pops nothing else.
R31. Shove (shove bubble.c:477, slide bubble.c:461). dy = pushY - bubbleY (pixels). Momentum is reset to 0 then one axis set to 3 px/tick (SHOVE_SPEED): push UP -> bubble goes up; else dy < -4 (push above bubble) -> bubble goes down; dy > 4 -> up; |dy| <= 4 -> along the push direction (left/right). (Hit zone bands: middle 9 px, upper 5, lower 5, out of the 19 px where overlap<10 holds.)
R32. A shoved bubble ignores the air and the vacuum, slides: pos += v, clamp; if the clamp changed the position, that axis' momentum becomes 0 (stops at the room edge / ceiling y 22 / floor y 202; walls and platforms do not stop it); else v -= v>>4 (x15/16, truncating shifts), and below 0.125 px/tick (SHOVE_STOP FX(0,32)) it becomes 0 (the air takes over again at the next tick). From 3 px/tick this takes 54 ticks and about 44.7 px. While sliding the 16-tick air reading is skipped, but age still runs (life/expiry unchanged).
R33. A shoved normal FLOAT bubble (empty) calls catch_enemy every tick, so it traps like a fired bubble (and a Riveter plate bursts it). A shoved TRAPPED bubble just slides (no trap).

## A7. Touching, bouncing, standing (player.c:471-486, 479)
R34. Bubbles are NOT solid. A player standing/walking never stands on a bubble; nothing stands on one.
R35. touch_bubbles (player.c:471): per tick for every FLOAT or TRAPPED bubble (specials and letters too, but not SHOOT and not POPPING) with overlap w=h=12 (strict, top-left) of the player (dash: w=14, h=20). For each:
   - bounce, if not dashing AND player vy > 0 (falling) AND jump button B held AND player top +8 <= bubble top (PX(py)+8 <= PX(by): the player's feet are above the bubble's centre-ish): the player gets the jump speed (2.57 px/tick up, 42 px high), jump sound, bubble stays (any kind). This is how players get up.
   - otherwise pop it: bubble_pop(b, dir = -1 if the player faces left else +1, owner = player id).
   The loop goes through all 16 bubbles, so one tick can pop several and also bounce on one.
R36. A dash always pops (no bounce), on the 14 x 20 band.

## A8. Popping and chains
R37. bubble_pop (bubble.c:153): only FLOAT or TRAPPED. Sets trapped flag (copy of state==TRAPPED), state POPPING, pop_timer = 1, and writes the global chain direction and chain owner (last pop call wins for everyone). The touched bubble bursts in the same tick's bubbles_update (timer 1 decremented to 0 in its slot). A bubble that is POPPING does not move, does not separate, is not hit by push, and cannot be popped again.
R38. burst (bubble.c:244) in this order, by what the bubble is:
   a) Holds an enemy: food tier = min(chain_kills, 6) (food 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 32,000 / 64,000 by the thrown item). The enemy is thrown as a food item: first enemy of the chain flies in the chain direction (the direction the popper faces), every later one in a random direction (-1/+1). chain_kills++ (cap 255). Then multikill_kill(chain_owner, chain_kills): the 3rd enemy plays the multikill sound (replacing the kill sound), kill sound for others, and counts 3rd/4th/5th kill of one chain as 1 letter bubble each for the owner (queue max 6, effect.c:418-429). No +10 points, no popped-count, no pop sound of its own.
   b) Letter bubble: blasen_collect(chain_owner, letter) (the owner gets the letter) + puff. No points here.
   c) Water/Fire/Lightning: effect_start(kind, x, y, dir, owner) + pop sound. dir = chain direction, except lightning which flies the opposite way (-chain_dir) (away from the popper); in the boss fight (boss_fighting) lightning flies toward the boss: right if boss centre x > bubble x + 8 px else left. A water bubble counts g_count.water (cap 255; 5 water pops unlock the umbrella). If the effect table is full nothing happens (silently).
   d) Empty normal bubble: puff, +10 points to the chain owner (score_add pos 1), g_count.popped++ (cap 255; 35 unlock speed candy), pop sound.
   Then the bubble is OFF and EVERY floating bubble (FLOAT or TRAPPED; not SHOOT; not already POPPING) in reach becomes POPPING with pop_timer = 5 (POP_DELAY) and keeps its trapped flag.
R39. Chain reach (in_chain_reach bubble.c:235): on integer pixels, |dx| < 18 AND |dy| < 18 AND |dx|+|dy| <= 25 (CHAIN_REACH, CHAIN_DIAG). So a diagonal neighbour at (17,17) (sum 34) is not in reach; (12,13) is; side by side up to 17. Special and letter bubbles chain too (they burst by their own rules, with the owner of the whole chain).
R39a. Timing: a link bursts 5 ticks after being lit; because of slot order inside one tick, a bubble with a HIGHER slot index than the bursting one is lit and then decremented in the same tick, so it bursts 4 ticks later; one with a lower index, 5 ticks later. So the chain is not strictly 5 ticks per link.
R39b. Chain counter lifetime: chain_kills (shared by both players, one static counter) is reset to 0 at the end of bubbles_update when no bubble is POPPING any more AND the chain owner is not in a dash (player_dash_invulnerable = dash running, not the grace time) (bubble.c:631-636). So everything that pops in one dash, however far apart, is one chain (food tiers and multikill counting continue). Two pops in the same tick (also by two players) also continue the same counter. A lone popped bubble with an enemy resets it at the end of that same tick.

## A9. Special bubbles
R40. Special bubbles come from effect.c:328-344 via bubble_spawn_special(kind, letter, x, y): position from level_opening (top or bottom opening), state FLOAT, direction UP, age 1, no momentum. Kinds: water (BK_WATER, sprite 128), fire (129), lightning (130), letter (131.. by letter). They float like normal bubbles at 0.35 px/tick, can be bounced on (R35), popped by touch, by chain, by the push bubble. Life 1200 ticks (R27). Not replaced by alloc_bubble (R2). In the boss round every fired bubble becomes LIGHTNING when its flight ends (age reset to 1, 1200-tick life), including one that was stopped by the boss (bubble.c:369-373).
R40b. Effects (water stream, fireball, bolt) live in effect.c; bubble.c only starts them at the bubble's position with direction +-1 and the pop owner.

## A10. Boss (boss.c): the Grumble Boiler, round 100 (level kind BOSS; spawned at round intro game.c:526, boss_reset on other rounds)
R41. Size 32x32 (4 sprites). boss_touch(x,y) (boss.c:91): only while fighting; object centre (x+8,y+8) against boss centre (boss+16): |dx| < 20 and |dy| < 20. Used by: fired bubbles (end their flight), push bubbles (burst), the players (enemies_touch -> TOUCH_DEADLY: touching the boss kills, even with rescue on; enemy.c:218) and the glove fireball (fizzles).
R42. Start: HP 24, position x=112, y=24 (BOSS_TOP = FIELD_Y+8), moving right and down, spit timer 100 (boss.c:44-54).
R43. Movement each tick while fighting (boss.c:133-150): x and y both move by the same speed, diagonal, bouncing: x range 16..208 (BOSS_LEFT 16, BOSS_RIGHT = 256-16-32), y range 24..160 (BOSS_BOTTOM = 224-8-32-24). At the limit (PX <= 16 / >= 208, <= 24 / >= 160) the position is set exactly to the limit and the direction flips (per axis independently). Speed by HP: hp > 12: 0.5 px/tick (FX(0,128)); hp 7..12 (hp <= 12): 0.859 (FX(0,220)); hp <= 6: 1.125 (FX(1,32)).
R44. Spitting: spit_timer counts down each fighting tick; at 0 it spits and reloads 100 (hp > 12) or 64 (hp <= 12). The boss spits at the nearest player (player_nearest from the boss's top-left): direction left if PX(player x) < PX(boss x) + 8, else right (tie -> right). 3 soot balls at once, starting at boss x+8, y+16 (top-left of the 16x16 ball, i.e. below the middle, centred), all with horizontal speed 1.25 px/tick (FX(1,64)) in that direction and vertical speeds 0.5, 1.0, 1.5 px/tick downwards (FX(0,128) + k*128). Shoot sound. Balls fly through platforms; they vanish when centre x < 16 or > 240 or top y >= 208 or < 16 (item.c:198-204). A ball kills a player at overlap 8x8 (enemies_touch). Mouth open sprite (SPR_BOSS1) when spit_timer < 20, else SPR_BOSS0 (boss.c:200).
R45. Hurting it: only a lightning BOLT (effect, from a lightning bubble) hurts it: boss_hit_by_bolt: bolt centre vs boss centre |dx| < 22, |dy| < 22 (boss.c:97-113). The bolt is used up on every touch (returns 1). Damage 1 HP only if the boss is not in its hurt window (20 ticks after the last hit, HURT_FRAMES); then sound KILL. A bolt that touches inside the hurt window does nothing and is gone. The boss flashes red (palette) while hurt & 4 (4 ticks on / 4 off). Water/fire do nothing (fire glove fireballs fizzle: effect.c:287). Players can bounce on or pop bubbles near it freely; the boss does not push or pop floating bubbles; floating bubbles pass through it.
R46. Lightning bubble aiming in the boss fight: popped bolt flies horizontally from the bubble's position to the side where the boss centre is (R38c). A chain of several lightning bubbles fires several bolts in the same tick, but the hurt window limits damage to 1 per 20 ticks.
R47. HP 0: state TRAPPED (giant bubble), soot balls removed (items_clear_rocks), trap sound. Fighting stops: no more spitting or moving sideways; boss is no longer deadly (boss_touch is false) and no longer hurt-able; bolts pass. Bubbles fired afterwards are still turned into lightning (level kind test) but harmless.
R48. Trapped phase (boss.c:160-178): moves vertically only, 0.25 px/tick (FX(0,64)), toward y = 80 (TRAPPED_Y = FIELD_Y+64) and stays there; x stays where it was. A player in state ALIVE (not dying/rescue) whose centre is within |dx| < 24 and |dy| < 24 of the boss centre pops it by touch (players in index order, first wins): POPPED, +100,000 points to that player (score_add pos 5 digit 1), two puffs at the boss's top-left and +16,+16, clear sound. Bubbles/bolts cannot pop it. 120 ticks later the ending starts (game.c:866) (ending: see game.c).
R49. HUD while fighting (game.c:856-863): "BOILER" in red at col 5 row 2 plus a bar of 12 cells, cell k (0..11) is a '#' if 2k < hp, else '-': hp 24 -> 12 cells, hp 23 -> 12, hp 22 -> 11, hp 3 -> 2, hp 2 -> 1, hp 1 -> 1 (so an odd HP shows one more cell than the half).
R50. Trapped drawing: giant bubble (4 sprites, SPR_GIANT_BUBBLE) drawn first (in front in OAM order), boss body underneath in the grey palette (boss.c:193-198). Not drawn when OFF or POPPED.
R51. boss_update runs after bubbles/enemies/chaser and before items and effects within a tick; it does not run while all players are dying. boss_hp() returns 0 unless fighting.

## A11. Drawing priorities (bubbles_draw bubble.c:639-699)
R52. Special/letter: single sprite, hidden on ticks with age&4 from age >= 1080 (also when popping untrapped). Trapped (and popping-with-enemy): ring sprite (by age: normal, orange from 120, red flashing from 210) + small enemy sprite over it. Else normal bubble: red flashing >= 540, orange >= 420, else blue; SHOOT stays plain. Push bubbles drawn last with their own sprite (SPR_PUSH). Each object = 1 OAM sprite (rings 2).

## A12. Plus vs Classic (the only differences inside bubble.c)
R53. Plus only: point-blank wall pop (R11), shots stop at walls/platforms (R10), upward shots (R5), push bubble (A6), vacuum (R21), dash chain-holding (R39b) and dash popping (R36). Everything else (drift, separation, soap, chain reach, expiry, trapping, boss) is identical in both modes. In Classic shots only know the room's side limits.

==================================================================
PART B: HIDDEN DECISIONS
==================================================================
H1. bubble.c:366/580: the flight is 9 moves, not 8: age is incremented before update_shot and the test is `age > shot_frames`. Distance 36 px (design guide says 32); range candy 15 moves = 60 px; speed candy 54; both 90.
H2. bubble.c:366-368: on turning to float the age is not reset, so life 600 counts from firing and the first 16-tick air reading comes 7 ticks later (1 with range candy at age 15); until then the bubble floats UP because dir = AIR_UP.
H3. bubble.c:362-366: order in a shot tick: wall stop (Plus) beats enemy trapping: a bubble that stops at a wall does not catch an enemy overlapping it that tick. But the trap test happens before the age-limit test, so the last move can still trap.
H4. bubble.c:358-361: wall stop restores the position from before this tick's move (up to 3.99 px in front of the wall, not flush); in Plus the leading edge is only a single point at 6 px from the centre (thin platforms/corners can be slipped past by the 16 px body).
H5. bubble.c:116-118,123-127: Plus point-blank test uses the centre tile; the "popped at once" bubble is not counted in blown but player.c still charges cooldown, Bubble Ring points and plays the shoot sound (player.c:459-464).
H6. bubble.c:76-92: free slot has priority by index; only if none is free the oldest plain float bubble is destroyed silently (strictly greater age, so ties keep the lowest index). With 16 non-replaceable bubbles a shot (and a letter!) is silently lost (letters: bubble_spawn_special also returns without spawning).
H7. bubble.c:94-112 vs 121-151: spawn does not reset `owner` (never written anywhere: dead field), `etype`, `letter` (normal) or shot fields; special bubbles start at age 1, fired at age 0.
H8. bubble.c:604-606: no-air tile -> random direction every 16 ticks (rng & 3, 1..4): uniform, 4 values. Air bits 5-7 (if ever in a map) give direction 5..7 = no movement (drift default).
